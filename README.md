# Signal research companion

Start with [START_HERE](START_HERE.md). This directory is independent of `quant-research-agent` and the synced project `sources/` directory.

## Run locally

An isolated `.venv` is included on this machine. From this directory:

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m signal_lab.demo runs/my-first-demo
.venv/bin/python scripts/render_report.py runs/my-first-demo reports
.venv/bin/python scripts/execute_notebooks.py
```

Use a **new output directory for each demonstration**; existing evidence is never overwritten. The report renderer intentionally regenerates the report from the selected run. Notebooks execute synthetic examples in temporary directories and make no API calls.

For a fresh environment with Python 3.10+:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[notebooks,sources]'
```

The tested dependency snapshot is `requirements-tested.txt`. The core has NumPy/pandas/Matplotlib; notebooks add nbformat/nbclient/nbconvert/ipykernel. OpenRouter uses the standard library. No global settings or credentials are changed.

## Boundaries

- `signal_lab/`: reusable teaching code, explicit contracts, persistence and a live-call adapter.
- `data/`: synthetic fixtures are generated by code; frozen public source inventory and catalogue snapshots are local references.
- `references/`: original guide preserved byte-for-byte. Its own prior verification claims are inherited, not automatically re-established here.
- `notebooks/`: ready-to-run examples, not completed learner exercises.
- `reports/`: generated outputs; regenerate from a recorded run rather than editing figures.
- `docs/`: editable canonical course notes, source map and ledgers.

The teaching harness executes registered Python functions serially. It is not a sandbox for untrusted generated code. The RLM exercise replays a scripted access policy; the evolution example constructs an overfitting failure. Neither is a measured agent benchmark. Future live agents need a separate evaluator process with inaccessible labels, restricted tools and protected timing/cost rules.

No `.env` loader is provided. An eventual live OpenRouter experiment reads only `OPENROUTER_API_KEY` deliberately supplied to its process. Never put a key in a notebook, prompt, saved output or commit.
