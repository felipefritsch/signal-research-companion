# Working glossary

| Term | Meaning in this lab |
|---|---|
| Model | A parameterized predictor or generator; not the entire application |
| Harness | Instructions, tools, control flow, state and checks around a model |
| RLM | Model-directed inspection of external context with sub-LM work available |
| Scripted fixture | A deliberately supplied response or policy for testing mechanics |
| Typed output | An output restricted to a structure; it may still be semantically wrong |
| Calibration | Agreement of reported probabilities with event frequencies across comparable cases |
| Abstention/review | An application decision to obtain more information or human review |
| Evidence lineage | Recoverable links from a claim or value to its source and transformation |
| Information set | What was available at the decision, including tools and model weights |
| Predictor | An input used to forecast; not automatically a risk factor or tradable portfolio |
| Factor portfolio | A specified mapping from signals into holdings and returns |
| Additivity | Incremental value relative to a stated incumbent and objective |
| Holdout consumption | Using a result to choose the next design makes that result development evidence |
| RRSI-inspired | A local design borrowing selected ideas, not the paper's full algorithm |
| Diffusion language model | A generator that iteratively refines token sequences; architecture alone does not establish task quality or speed |
| Cost per valid task | Total measured spend, including failures, divided by valid completed tasks; undefined when none pass |
| Time to first token | A streaming latency metric; not measured by this non-streaming adapter |
