# Interview walkthrough — truthful project evidence

This is a technical discussion guide, not a claim about previous employment. Code and initial worked materials were generated with Codex. Felipe's individual implementation and explanation evidence is tracked separately in the learning record.

## A concise explanation

The question behind this project is how to use agents to make research more reliable. The difficult part is deciding what an apparent improvement actually means: better evidence, a useful prediction, or simply a shortcut that scores well on familiar tasks.

The initial lab, built with Codex, separates those questions. It has worked examples for probabilistic decisions, document investigation, recoverable tool execution and harness selection. One example shows how a development-specific rule can win the selection process and then fail on a different task set. Another shows why a historical return is overstated if the strategy could only enter after part of the move.

These are controlled teaching examples. Live-model comparisons and a financial signal evaluation come later, with separate standards of evidence. My own implementation and explanation work will be recorded as I complete the course.

## Walk through one result

Start with the 100 → 104 → 105 example. Explain why 5% close-to-close performance cannot be credited when entry is 104. Show the independent arithmetic and the persisted calculation. Then explain how an unrestricted optimizer could inflate its score by changing the entry definition.

## Connect the four modules

- Jev/System One: bounded probabilistic judgments, with application-specific consequences.
- RLM: adaptive investigation of externally stored material; our initial notebook is explicitly scripted.
- Prime Agent/harnesses: runtime state, tools and delegation; our local runner is much smaller and serial.
- RRSI: selecting reusable improvements; our counterexample borrows screening and complexity ideas but does not reproduce the paper.
- OpenRouter: optional comparison of models by role, accounting for quality, latency, capability and total cost. No live comparison has run yet.

## Defend the research design

For Baker's headline-return question, lead with the pretrained-model information problem. Establish the model version, source vintages, decision timestamp, return window and search history. Propose prospective shadow predictions where feasible, then assess mechanism, prediction, costs and additivity. Do not declare a strategy ready from a single favorable backtest.
